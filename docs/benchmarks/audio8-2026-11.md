# Audio8 engines: streaming, throughput, VRAM, German WER (2026-11-02)

All numbers were measured by a client over HTTP against the real server (`omnivoice_tts_server.main`), through the
public API. Nothing here was timed in-process.

Four engines share one implementation. **Their licences differ:**

| Engine | Model | Runs on | Licence |
| --- | --- | --- | --- |
| `audio8_realistic` | Audio8 Realistic 0.6B | GPU | Apache-2.0 |
| `audio8_preview` | Audio8 Preview 0.6B | GPU | Apache-2.0 |
| `audio8_mini` | Audio8 Preview 0.1B (Falcon-H1) | GPU | **Audio8 Community License v1.0: commercial use only below US$2M annual revenue** |
| `audio8_onnx` | Audio8 0.1B ONNX INT8 | CPU | Apache-2.0 |

## Hardware and software

- One RTX 5090 32 GB (cuda:0), Ryzen 9800X3D, Windows 11 (WDDM).
- `.conda-env`: Python 3.12, torch 2.10+cu130, transformers 5.9.0. The Docker image and the lock file use 5.10.2, where
  the Audio8 GPU engine tests pass too. These benchmarks ran on 5.9.0 only.
- Repo: working tree on top of `300cfb2`, Audio8 not yet committed.
- Audio8 output 44.1 kHz. Sampling: temperature 0.8, top_p 0.95, top_k 50. GPU engines: bf16 language model and codec,
  CUDA graphs on, chunks of 4 then 12 frames, `batch_wait_ms` 0.
- `max_queue_size` 256, so the benchmark never hits the queue limit.

**One thing differs from the Ming benchmark.** A G3_Whisper process that an earlier step had started stayed resident on
the card during the speed runs. It idled at 0 % GPU use and held memory, so the baseline was 9.94 GB instead of about
1.06 GB. The baseline was the same before 11 of the 12 runs and 8 MB higher before the other, and VRAM figures are deltas
to it. Whether this idle process cost any speed was not measured.

## Method

Same scripts and load patterns as [ming-3.0-tts-2026-10.md](ming-3.0-tts-2026-10.md):

| Script | What it does |
| --- | --- |
| `bench_engine_streaming.py --spawn audio8_*` | Starts a server with the engine and preset in a throwaway data dir, runs the load patterns, samples `nvidia-smi` every 100 ms, stops the server. |
| `bench_wer_roundtrip.py --sentences-file wer_sentences_de.tsv` | Synthesizes each sentence through `/v1/audio/speech`, transcribes it with G3_Whisper and scores it with the server's own `WerBenchmarkService._wer`. |

- **TTFA:** from sending the request to the first non-empty audio bytes, on the client.
- **Burst of N:** N requests at the same instant, repeated 20 / 6 / 3 / 2 times for N = 1 / 4 / 16 / 32. ONNX: 20 / 8 / 6
  times for N = 1 / 2 / 4. Each request is one German sentence from the fixed list of 16.
- **RTF:** wall time of the request divided by the seconds of audio it returned. Lower is better.
- **Saturation:** C closed-loop clients for 45 s. Throughput is audio seconds of all completed requests per wall second.
- **VRAM:** whole-card `memory.used` minus the baseline before the server started. The figures include the CUDA context.

No request failed in any speed run.

## 4. German WER (G3_Whisper round trip)

The remote Whisper (192.168.20.146:7861) and vLLM (192.168.20.126:8000) were both offline. So:

- **ASR:** the local G3_Whisper on port 7861 (Cohere Transcribe), which holds 8–9 GB of VRAM.
- **Sentences:** vLLM could not write any, so this ran through `bench_wer_roundtrip.py` and not the admin benchmark, on a
  fixed hand-written list, `tools/benchmarks/wer_sentences_de.tsv`. There is no template fallback on this path, so
  `fallback_sentence_count` does not apply. These numbers cannot be compared with the 1000-sentence vLLM runs in the Ming
  benchmark.
- **Corpus:** 131 sentences: 50 plain, 51 with numbers, dates, times, units or abbreviations, and 30 long ones of
  170–208 characters. 3760 reference words per mode.
- **Clips:** voices Genesis3 and SonjaV2, modes `off` and `deterministic`: 524 per engine. Every clip was scored; none failed.
- **Seed:** each voice's own, no request seed. Ming and OmniVoice ran on the same list for a baseline, Ming 32 slots and
  OmniVoice `32GB VRAM` (25 steps).
- **Scoring:** the admin scorer, tolerance 2 letters per word.

`off` and 0 in `deterministic`, with byte-identical WAVs. Transcribed again, it came out correct. Without that clip Ming

Reading the table:

- **Plain and long text:** all four Audio8 engines are almost perfect. The 0.1B engines read one word wrong in the long
  group, the same word for both voices ("überquerte" as "überkehrte").
- **Digits are the weak spot, as on the other engines, and worse on 0.1B.** With raw digits (`off`) the 0.1B engines have
  twice the WER of the 0.6B engines. With `deterministic` the three GPU engines are level and within reach of Ming and
  OmniVoice. Clients that send digits should use `deterministic`.
- **ONNX** is the weakest in every mode, and the only Audio8 engine with an error in plain text.

### Dropped words

The known risk was that Audio8 drops a clause of long sentences. **No Audio8 engine dropped a word in any long sentence**
(170–208 characters, about 60 distinct renders per engine). That is what this sample shows, not proof that it cannot happen.

The scorer counted these deletions in all clips:

| Engine | Off | Deterministic | Words really missing from the speech ⁵ |
| --- | --- | --- | --- |
| Realistic 0.6B | 9 | 4 | **6 words in 4 clips, all SonjaV2, mode `off`:** "89,90 [Euro]", "8,50 [Euro]", "9,99 [Euro im Monat]", "6,40 [Meter]" |
| Preview 0.6B | 4 | 4 | none |
| Preview 0.1B | 4 | 4 | none |
| ONNX INT8 | 8 | 6 | **1 word, SonjaV2, both modes:** "während [der] Vorstellung"; in `off` also garbled numbers ("89,90 Euro", "6,40 Meter") |
| Ming | 8 | 4 | none (the 6 of footnote ⁴ are the transcription failure) |
| OmniVoice | 3 | 4 | none |

⁵ Read from the transcripts. Nobody listened to the clips, so a word Whisper missed would look the same.

The other deletions are not missing speech:

- "A 7" transcribed as "A7": every engine, a scoring artefact.
- "z. B." and flight numbers read or transcribed as one word.
- "vom 4. bis zum 6. September" in `deterministic`: every engine. The optimizer itself rewrites it to "vom vierten bis
  sechsten September" and removes "zum".

**Realistic drops units after a raw decimal number.** All four missing-word clips are this pattern, so this checkpoint
needs `deterministic` when text has prices or measurements. With `deterministic` none of them happened.

## 6. Output rate on the raw stream

With one seed, the raw PCM stream had exactly as many frames as the WAV on all six engines. The Audio8 WAVs are
44.1 kHz, so **raw `/v1/audio/speech` streaming on Audio8 is 44.1 kHz, not the 24 kHz of the other engines**. The stream
has no header. A client that assumes 24 kHz plays it too slow and too low. It should read `sample_rate` from
`GET /api/v1/capabilities`, or the admin sets `audio8_output_sample_rate=24000`. The 24 kHz setting was not part of this
benchmark.

## Caveats

- **Nobody listened.** All quality statements come from transcripts. Voice similarity, prosody and chunk seams in streamed
  audio have not had a listening test.
- **Nothing was measured on an RTX 3090.** The 24 GB tiers on the 3090 are calculated.
- **Short sentences only** in the speed runs. Long texts go through the queue and the engine's fragment limit
  (`audio8_fragment_max_chars` 200).
- **Single runs.** Differences of a few percent between the 0.6B engines are noise.
- **WER sample size.** 262 clips per mode, with one seed per voice. Differences of a few clips are not meaningful.
- **Possible underrun on the first chunks at full load.** The first chunk is 4 frames, the next 12. No gap measurement
  was made under load; `stream_prebuffer_ms` would cover it.
- **Only raw TTFA is reported here.** The runs used a script that assumed 24 kHz for raw RTF, which it no longer does.
- **OmniVoice and Ming speed figures are from 2026-10-28,** without a resident Whisper process.
